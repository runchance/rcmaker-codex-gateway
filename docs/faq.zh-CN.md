<a id="network"></a>
## 启动与网络

### 控制台打不开，先检查什么？

确认 RCMAKER 进程还在运行，启动窗口没有端口冲突，并且在同一台电脑使用配置的控制台端口。默认地址是 `http://127.0.0.1:28910/`。不要为了修复一个实例，又启动第二个实例占用相同端口和数据。详见[安装步骤](user-guide.zh-CN.md#install)。

### 支持哪些代理？

控制台支持直连或显式 **HTTP CONNECT** 代理。填写代理软件实际提供的 HTTP 主机/端口，不能换成仅支持 SOCKS 的端口、`socks5://...` 或任意系统代理设置。主机字段不含 URL 协议头。先保存网络，再下载组件。

### 为什么出现 HTTP 403，网络检测仍可能成功？

TLS 连接完成后收到目标网站 HTTP 响应，证明通路可达，不证明登录与模型权限可用。代理拒绝 CONNECT 隧道返回 403 则不同，属于网络失败。网络确认后再完成私有浏览器账号与模型检测。字段见[网络操作](user-guide.zh-CN.md#setup)。

### 下载 Chrome 也走代理吗？

应用浏览器、运行组件下载与工具隧道使用保存的网络配置。确认配置已保存/应用、代理运行正常；重试前查看下载错误和磁盘空间。不要用关闭证书校验或更换不相关下载源来掩盖问题。

## 连接器

### ChatGPT 创建插件失败，正确顺序是什么？

先准备组件并登录，在 RCMAKER 保存 **Tunnel ID＋普通运行 API Key＋连接器名称**，等待隧道已连接。然后去 ChatGPT 创建对应 Tunnel、对应名称的自定义 MCP 插件，最后回控制台“检查连接器”。[图文步骤](user-guide.zh-CN.md#connect-tools)有完整截图。

Tunnel 不出现在列表中时先检查账号/工作区访问关系，不要反复创建重复项。外部配置要求参考 [OpenAI 官方说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。

### 用 Admin key 吗？Codex 和 ChatGPT 必须同账号吗？

使用具有 Tunnel 所需权限的**普通运行 API Key**，不是 Admin key。控制台预期 Tunnel、Key 与私有浏览器 ChatGPT 身份对应；桌面 Codex 可以是另一登录账号。组织与工作区权限仍需匹配，邮箱相同本身不等于权限检查通过。

### 连接器必须叫 RCMAKER Codex5 吗？

不是。新安装默认 **RCMAKER Codex**，`RCMAKER` 为固定前缀，后缀可修改。已有安装保留保存的名称。把完整名称原样填到 ChatGPT；改名后新建名称匹配的插件并核验。任务进行中不要修改连接身份与凭据。

### 每次重启都要重新创建或手动检查连接器吗？

普通重启会按已保存配置重新连接，重复创建插件不是启动流程。“检查连接器”测试实际连接；ChatGPT 的 **Refresh tools / Refresh**刷新缓存工具定义，适用于发行版本修改工具 schema 的情况。两者不同。

### ChatGPT 菜单不一样，或者没有 Developer Mode，怎么办？

参考当前[添加自定义 MCP 服务器说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)。入口可能随账号/工作区位于 Plugins、Apps 或 Developer Mode。核对 [Developer Mode 文档](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)与工作区权限；RCMAKER 不能授予账号本来没有的功能。

### 原生窗口已经登录，控制台还没更新？

回到运行准备，等待账号/模型检测，需要时点“刷新状态”或“刷新页面”。确认登录的是 RCMAKER 私有原生窗口，不只是系统 Chrome。不要一上来清空所有 Profiles，否则会丢失登录状态并需要重新登录。

<a id="models"></a>
## 模型

### 保存接入后，Codex 里看不到 Web 模型？

完成“检测可用模型 → 预览接入配置 → 保存接入配置”，然后完全退出并重开 Codex，包括后台进程，RCMAKER 保持运行。新建聊天不等于重载模型目录。维护多个 Codex 安装时，还需核对配置的 Codex home。

### 怎样区分网关模型和原生 Codex 模型？

网关条目以 **RC (Web)** 结尾。家族名称跟随官网选择器，例如 `GPT-6 · Thinking · RC (Web)`，不保证始终有这个型号。上下文窗口不同的模式分开列出，Thinking 保留实际可用的推理强度选择。

### Pro 在哪里？需要开启 Ultra 吗？

检测可用时选独立的 **… · Pro · RC (Web)**，不必为了选 Pro 而开启 Codex Ultra。Pro 不可用时会从新选项中隐藏，检测到恢复后重新加入；旧别名不会带来额外权限。核对私有 ChatGPT 实际选择器、刷新模型检测，目录过期时重开 Codex。不可用的 Pro 请求不应悄悄降为其他档位。

### 为什么截图里的模型与我的不一样？

截图名称与数据只是操作示例，账号套餐、额度、下线安排和官网变化都会影响真实列表。以自己的检测结果为准。网关的 token 预算属于实现策略，不是 OpenAI 模型最大上下文的声明。

<a id="history"></a>
## 上下文与历史

### 3× 历史会让模型上下文扩大三倍吗？

不会。它扩大历史接入与传输处理预算，不改变模型实际记忆窗口。较早执行记录可以通过可读历史交接继续供查询，长任务仍需要压缩。

### 最大六段就是每次发六条吗？

不是。新请求根据预算和上限选单条或 **2–6 段**中合适的最少段数；已保存的传输事务恢复时保留原段数。更多分段增加传输时间，不增加模型容量。开启 3× 要求六段上限。

### 对话只有两轮就分段或压缩，正常吗？

可见用户消息条数不等于总上下文。指令、技能、历史工具结果、附件及继承/分叉历史都占容量。查看时间线的**上下文发送与压缩决策**，对照当前模型/模式和历史设置；不同模式预算可能不同。反复压缩但没有进展值得排查，不能仅凭频率认定丢失上下文。

### 压缩后所有内容都逐字保留吗？

网关通过摘要、保留的用户原文、近期附件、可查询记录和工具回执校验维持可用连续性。摘要不是所有历史的逐字副本。需要某个准确旧值时核对保留证据，不能把无法读取的加密块当成已经恢复。

### Web 模型能直接读取 Codex 官方加密历史吗？

不能直接解密提供方私有检查点。默认保留已有可读历史并标记不可读部分；可选的**官方模型交接摘要**会用当前官方 Codex 登录生成可读摘要，可能消耗对应额度，默认关闭。也可以用新的可读项目需求补充继续工作所需的信息，详见[接入恢复](user-guide.zh-CN.md#upgrade)。

### 图片和技能文件会传过去吗？

当前控制台说明每次最多上传 **10 个文件**：自动选择近期图片，勾选上传的已选技能文件共用这些名额。默认技能指令以正文传递，不占上传名额。这是网关当前传输策略，不是 ChatGPT 通用文件上限。某张图很重要时，核对任务原文与附件记录。

<a id="recovery"></a>
## 任务与恢复

### 网页提示“连接中断”，但工具还在执行？

可见警告可能残留，而同一任务仍在生成或等待工具完成。取消前核对实际回执与时间线，不要在写入可能正在执行时反复重发或点重新生成。最终回答应在所需结果到齐后结束；网页确实结束而 Codex 一直不结束时，记录两侧状态与时间反馈。

### 409 冲突代表什么？

看完整文案。“未知执行结果”“任务已取消”“同一 turn ID 用于不同请求”“摘要已在进行”属于不同状态冲突。先看该任务时间线。已取消能力不应复用，可能已经执行的操作不应盲目重放。处理/取消旧工作后通过 Codex 提交新请求；普通续接持续报 409 时，提供版本和脱敏时间线，不要手工删数据库。

### `context_json` 无法解码、`SCHEMA_MISMATCH` 怎么处理？

保留准确错误码及脱敏发送原文，通常需要排查格式/协议，不能直接推断为密码错误或要求重建所有账号。1.0.4 包含浏览器提示插入历史 JSON 导致损坏的修复，但新出现的解码错误仍需单独证据。不要手改数据库历史让解析器勉强通过。

### 模型说“安全检查拦截”，如何确认？

查看是否有明确工具结果、授权拒绝或平台错误。模型最终文字里的一句话，不足以证明工具已经执行或被拦截。授权与工具权限由 Codex 及所连平台负责；先看真实拒绝原因，不要将被拒绝的操作改走另一工具。

### 任务没结束时可以插话吗？

可以，在同一条 Codex 对话里明确说明补充、纠正或询问。网关传递中途引导，交接可能新建临时网页。只是顺便问一句时，可明确要求继续原任务；如果回答后异常结束，保留时间线以定位具体交接过程。

### 每个开发任务都应该跑几个小时吗？

不需要。小任务可以很快完成。应看文件变更、真实工具结果、测试和是否达到目标；网关反复发“继续”、计时很长或调用次数很多，都不能单独证明质量。

<a id="usage"></a>
## 用量

### 控制台的 Pro 剩余次数是官方数据吗？

除非明确具有官方余额依据，否则不是。常规显示来自本机滚动七天记录与填写的跟踪预算，不包含其他设备和直接网页活动。“未提供”表示没有官方余额，不是剩余零次。估算 Token 也不是账单。

### 历史分段、摘要会浪费 Pro 消息吗？

当前策略对历史接入/连接检查使用非 Pro 中档，对网关摘要使用非 Pro 高档，并使用所选家族支持的模式；实际用户任务使用选定的模型/强度。应核对记录中的用途与实际发送档位，不要把每个新网页都当成 Pro 调用。

### 是否仍可能消耗官方 Codex 配额？

会：选择官方模型走原生转发，或主动开启可选的官方模型交接摘要时。后者默认关闭。本机用量估算不能涵盖官方账号所有费用，需另看账号提供方的用量信息。

<a id="cleanup"></a>
## 清理与存储

### 删除任务会删除项目或 Codex 聊天吗？

任务中心清理针对网关中符合条件的任务记录，不针对项目源文件或 Codex 聊天本身。运行中任务和授权等待会跳过，部分检查点凭证及被引用附件为后续连续性保留。删除前看确认提示；手工删除数据库不等于使用支持的清理流程。

### 已清理任务，为什么 SQLite 文件还是很大？

删除空间可能先在 SQLite 内部变成可复用空间，文件回收要等活动任务空闲。看控制台占用、可复用空间和清理进度，不要只看文件大小。程序运行时不要删除 `-wal`、`-shm` 旁文件。

### 升级或换机器要保留什么？

原目录升级保留 `.env`、配置的 `data` 与可回退的旧程序，备份前停止活动写入。换机器可能影响受系统保护的凭据与浏览器会话，不能保证复制 Profiles 就恢复所有登录；私有备份不要公开，必要时重新登录。详见[升级操作](user-guide.zh-CN.md#upgrade)。

## 怎样反馈问题

附上版本、操作系统、模型/档位、大致时间、完整错误，以及发生在启动、生成、工具等待还是压缩阶段，并提供脱敏时间线。移除 API Key、Cookie、turn token 与私有提示词。说明真实观察到的结果，不要推测重试已经成功。
