## 1. 开始前准备

整个流程涉及三个界面：

| 界面 | 在这里做什么 |
| --- | --- |
| **Codex** | 打开项目、选模型、发需求、处理授权、检查文件变更 |
| **RCMAKER 控制台** | 配置连接、查看浏览器实况、任务与本机用量 |
| **私有 ChatGPT 浏览器** | 登录网页模型账号，创建其使用的自定义插件 |

先安装 Codex，准备具有所需模型和自定义 MCP 应用功能的 ChatGPT 账号，以及具有相应 Tunnel 权限的 Platform 账号/工作区。控制台会引导配置 Tunnel 和普通运行 API Key；它们应与私有浏览器的 ChatGPT 账号对应，Codex 桌面端可以登录不同账号。工作区权限仍然适用。

不要仅凭订阅名称认定一定具备所有入口。缺少 Tunnel 或自定义应用入口时，核对当前 [OpenAI 自定义 MCP 应用说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)与 [Secure MCP Tunnel 文档](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)，包括工作区权限。

## 2. 安装并打开控制台

### 使用独立程序

将程序放入有写入权限的目录，例如 `D:\Apps\RCMAKER-Gateway`，**双击 `.exe` 文件就能启动**，无需传入 `start` 参数。也可以使用 PowerShell：

```powershell
cd D:\Apps\RCMAKER-Gateway
.\rcmaker-codex-gateway.exe
```

保持运行窗口开启。首次使用会在程序外部创建持久数据，无需复制其他机器的 `data`。在同一台电脑打开 **http://127.0.0.1:28910/**；修改过 `.env` 的 `console_port` 时使用新端口。

本图文流程以 Windows 为例。Linux/macOS 应使用针对目标系统构建并验证的版本；框架支持打包不等于网关已在该机器完成使用。

### 使用源码

在 Windows、macOS 和 Linux 上源码运行均支持 **PHP 8.1–8.5（含）**。建议先参照 [RCMAKER 官网快速入门：准备环境](https://rcmaker.runchance.com/doc/#/md/quick-start?id=_1-%E5%87%86%E5%A4%87%E7%8E%AF%E5%A2%83) 配置 PHP、所需扩展和 Composer，然后在本项目源码目录运行：

```sh
composer install
php index.php start
```

如需调整部署参数，可查看根目录的 `.env.example`（INI 分区格式），升级时请保留已有 `.env`。

### 认识控制台

主要入口为**运行准备、浏览器工作区、任务中心、设置**。新安装默认英文；语言选择器可切换中文，不会翻译用户对话或模型契约。

*图 1：按编号依次完成。是否就绪以你自己控制台的状态为准，不以示例截图为准。*

## 3. 网络、运行组件与登录

### 第一步：网络

进入**运行准备 → 设置网络**。可以直接访问所需服务时选“直接连接”；需要代理时选“使用 HTTP 代理”，填写地址、端口，再点**保存并测试**。

![代理 IP、端口及保存并测试按钮](images/user-guide/zh-CN/network.jpg)

*图 2：`127.0.0.1:7890` 只是示例，必须填写你自己的代理软件实际提供的 HTTP 监听端口。*

| 字段 | 填写方式 |
| --- | --- |
| 代理 IP/主机 | 例如 `127.0.0.1`，不包含 `http://`、路径或用户名 |
| 端口 | 代理软件的 HTTP CONNECT 端口 |
| 认证 | 代理需要认证时，在详细“网络与代理”设置中配置 |

这里支持 **HTTP CONNECT**，不能直接换用仅支持 SOCKS 的端口。设置只影响 RCMAKER，不修改系统代理；浏览器、组件下载与工具隧道使用同一份网络配置。

**完成标志：**控制台确认网络连接。目标网站返回 HTTP 403 仍可能证明网络/TLS 已连通，登录和模型权限另行检查；代理本身拒绝 CONNECT 隧道而返回 403 则属于另一种失败。详见[网络 FAQ](faq.zh-CN.md#network)。

### 第二步：运行组件

点击**准备运行组件 → 开始准备**，等待私有 Chrome 和工具隧道组件准备完成。

![运行组件准备弹层](images/user-guide/zh-CN/runtime.jpg)

*图 3：先保存网络再准备组件，保证下载使用预期通路。*

**完成标志：**运行组件卡片显示就绪。组件保存在应用数据目录中。下载失败时先检查网络与磁盘；反复创建连接器不能修复缺失的浏览器组件。

### 第三步：登录 ChatGPT

进入**登录 ChatGPT → 打开登录页面**，使用准备给网页模型使用的账号登录。

![私有 ChatGPT 登录控制，包括原生浏览器按钮](images/user-guide/zh-CN/login.jpg)

*图 4：内嵌画面与原生窗口共用 RCMAKER 私有浏览器资料。*

需要更直接地输入、滚动和粘贴时，点**打开原生浏览器**。打开的是项目私有 Chrome 独立窗口，不是系统 Chrome 的日常资料。登录后回控制台等待账号/模型检测；“收起原生浏览器”用于收起可见配置窗口，保留私有登录。面板状态未更新时先用“刷新页面”或“刷新状态”，不必马上重新登录。

**完成标志：**账号与模型检查通过。能看到 ChatGPT 首页不等于工具已连通，下一步还要检查连接器。

**清空内置 Chrome 登录资料**会移除 RCMAKER 保存的 ChatGPT/Google 登录与 Profiles，是主动重置账号操作，不是普通刷新。先结束任务再使用；它不针对系统 Chrome 或项目源文件。

<a id="connect-tools"></a>
## 4. 连接工具与 ChatGPT 插件

进入**运行准备 → 配置工具连接**。必须先让隧道工作，再去 ChatGPT 创建插件，否则无法发现本地工具。

### 4.1 创建 Tunnel 并保存连接

点击**打开 Tunnel 创建页面**，在对应 Platform 组织下创建 Tunnel，复制 `tunnel_...` 标识。再点击**打开 API Key 创建页面**，创建具有对应权限的**普通运行 API Key**，不是 Admin key。

![Tunnel ID、API Key、连接器名称填写区域](images/user-guide/zh-CN/tools.jpg)

*图 5：公开截图只有占位符，实际值仅在你自己的本机控制台填写。*

| 字段 | 要求 |
| --- | --- |
| Tunnel ID | 刚创建的 Tunnel 标识 |
| API Key | 对该 Tunnel 有权限的普通运行密钥；已保存的密钥不会重新显示 |
| 连接器名称 | 固定前缀 `RCMAKER` 加自定义后缀，新安装默认为 `RCMAKER Codex` |

点击**保存并连接工具隧道**，等待显示已连接。保存后配置即交给隧道生效，正常首次配置不应要求为了这一步重启 RCMAKER。

Tunnel/API Key 按钮在当前打开控制台的浏览器中开新标签；注意该浏览器登录的账号。插件创建使用私有 ChatGPT 账号。保持账号及工作区访问关系一致，不要因为密钥格式相同就使用无关账号的 Key。

### 4.2 创建名称匹配的 ChatGPT 插件

![创建连接器核对清单及检查按钮](images/user-guide/zh-CN/connector.jpg)

*图 6：本机清单会显示应填写的完整连接器名称，以及“检查连接器”入口。*

点击**打开 ChatGPT Connector 设置**，或该区域的**打开原生浏览器**。当前 ChatGPT 界面可通过 **Plugins/插件 → ＋ → Add custom MCP server/添加自定义 MCP 服务器**创建；较早界面的入口可能位于 Developer Mode 或 Apps 设置中。按当前 [OpenAI 创建说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)操作。

| ChatGPT 字段 | 填写内容 |
| --- | --- |
| Name/名称 | 与 RCMAKER 显示的完整名称完全一致，例如 `RCMAKER Codex` |
| Connection/来源 | **Tunnel**，选择你创建的 Tunnel |
| Authentication/身份验证 | 本集成使用 **No authentication / None** |

阅读 ChatGPT 显示的权限与提示，创建插件；当前界面要求安装/连接时完成该步骤。回到 RCMAKER，点击**检查连接器**。

**完成标志：**工具隧道与连接器检查均通过。插件名字已经保存，并不能证明实际工具通路正常。

更新工具定义时，ChatGPT 的 **Refresh tools / Refresh**用于刷新缓存的工具清单；RCMAKER 的“检查连接器”用于验证连接，不能代替刷新清单。普通重启不用重复创建插件。修改后缀后要新建名称匹配的插件并验证，详见[连接器 FAQ](faq.zh-CN.md#connector)。

## 5. 在 Codex 中启用 Web 模型

在同一弹层找到**在 Codex 中启用 Web 模型**，点击**检测可用模型 → 预览接入配置**，核对改动后再点击**保存接入配置**。

![模型检测、接入预览与 Codex 重启提醒](images/user-guide/zh-CN/codex.jpg)

*图 7：示例展示保存后的重启提醒。模型名称仅为示例，你自己账号的检测结果才是依据。*

接入管理自身的路由与模型元数据，并保留可恢复的备份，不覆盖无关项目、MCP 与权限设置。从其他网关切换时，原模型路由可能被替换，所以要先看预览。

> **完成配置后，等待 RCMAKER 的 Shell 控制台显示 `准备就绪。请启动 Codex；如果已经打开，请完整退出后重新启动。` 看到这条信息后，再启动 Codex，或者完全退出 Codex（包括后台进程）并重新打开。RCMAKER 保持运行。**

只有网络、内置浏览器、ChatGPT 登录、模型和连接器全部通过检查后才会出现该提示。如果控制台仍停留在等待某一步，请先在**运行准备**中完成配置。只关闭聊天或新建聊天无法重新加载模型目录。

可用网页模型名称以 **RC (Web)** 结尾，官网家族名后标注模式，例如 `GPT-6 · Thinking · RC (Web)`。Thinking 保留可用推理档位，Instant 与 Pro 使用独立固定模式条目，以适配不同上下文预算。示例不保证账号有该模型。使用网页 Pro 时选独立的 **Pro** 条目，无需仅为选它而开启 Codex Ultra。

**完成标志：**完整重启后 Codex 能看到新条目，控制台接入检查通过。

## 6. 首次任务与使用

在 Codex 打开目标项目，选择检测通过的 **RC (Web)** 模型。先提交一个小范围只读请求：

```text
检查这个项目的目录结构和 README，说明启动命令及缺少的配置。
这次不修改文件，回答要基于实际读取的文件。
```

核对整条链路：

| 查看位置 | 应出现的结果 |
| --- | --- |
| Codex | 原生工具调用与真实结果，随后给出回答 |
| 浏览器工作区 | 自动出现该任务的 ChatGPT 页面 |
| 任务中心 | 对应任务记录消息、回执与状态 |

通过后再给出明确开发任务：

```text
修复这个项目中指定的问题。先检查相关实现和测试，再修改代码，
运行适当的检查，发现失败继续修复。汇报实际变更和验证结果，
并明确指出尚未验证的部分。
```

需要权限时在 Codex 处理授权。网关不会绕过 Codex 的本地权限；最终文字声称成功不能替代真实文件变更与测试结果，请核对 diff 和输出。

## 7. 日常操作

### 浏览器工作区与并行任务

任务从 Codex 发起，不要在自动化占用的 ChatGPT 页面中直接输入另一份需求。工作区最多保留五个任务页面，区分活动/非活动，优先显示工作中的页面。容量不足时关闭符合条件的空闲页或等待，不要关闭执行中的页面。关闭页面与删除任务记录不是同一操作。

中途补充要求时，在**同一条 Codex 对话**发送。网关将消息作为当前任务引导，相关修改应并入任务，无关询问不应取代原目标，除非你明确要求暂停或替换。交接时可能新建临时网页，但 Codex 对话仍可延续。

### 任务中心、发送原文与清理

![任务中心状态分类与清理入口](images/user-guide/zh-CN/tasks.jpg)

*图 9：空数据示例展示状态分类；使用后任务会进入下方列表。*

从任务行的时间线操作查看网页交互、工具结果、上下文发送决策及异常状态。展开全量消息记录，可核对实际发送的完整契约与上下文，并使用**复制、下载**操作。“发送意图已记录”与“网页已确认接收”是不同证据。

状态分类包括可继续、需要确认、已完成、已取消。“清除所有非工作任务”只删除符合条件的非工作记录；生成中、工具执行中、等待审批的任务会跳过。删除前阅读确认提示。项目文件不属于清理目标，部分检查点和附件凭证会为续接保留。数据库回收空间可能要等其他任务空闲后完成。详见[清理 FAQ](faq.zh-CN.md#cleanup)。

### 日常设置、上下文与 Pro

![日常设置：语言、可选官方摘要与上下文参数](images/user-guide/zh-CN/settings.jpg)

*图 10：示例采用新安装的 3× / 六段组合，已有安装仍保留自己的设置。*

| 设置 | 实际含义 |
| --- | --- |
| 控制台语言 | 保存中文/英文界面偏好，不翻译对话与契约 |
| 最多 3× 历史 | 允许接入更多历史，不是模型记忆扩大三倍 |
| 最大分段数 | 上限而非固定条数，自动选择单条或合适的 2–6 段 |
| 官方模型交接摘要 | 默认关闭；开启后遇到加密历史交接可能消耗官方 Codex 额度 |
| 上传技能文件 | 可选，已选技能文件与最近图片共用上传名额 |
| Pro 每周跟踪预算 | 仅用于本机估算，应填写实际额度而不是照抄示例 |

首次使用保留默认值。3× 选项要求六段上限，降低上限不等于继续维持同样的 3× 行为。已开始任务沿用开始时的预算与设置快照；模型目录元数据更新后需完整重开 Codex。

历史预载使用所选家族的非 Pro 中档，网关摘要使用非 Pro 高档，实际执行使用你选的模型与档位，包括 Pro。压缩属于交接过程，不代表任务已经失败；异常频繁时先看决策记录，不要随意把所有超时拉满或删除历史。

**模型契约**位于独立设置页签，普通用户建议保持默认。确需修改模板时，必须保留必要变量，且不要填入任何真实凭据。

### 正确理解用量

**运行准备 → 账号与用量**显示检测账号、模型、近期网页提交、Pro 次数和估算 Token。统计范围是本机安装最近滚动七天，不包含其他设备或直接网页对话。预计余额不是官方剩余额度，也不代表官方重置时间。详见[用量 FAQ](faq.zh-CN.md#usage)。

## 8. 升级、恢复与排错

### 原目录升级

1. 等任务与授权等待结束，保存 Codex 工作，按日常方式停止 RCMAKER。
2. 私下备份原 `.env` 与持久 `data`，保留旧可执行程序便于回退。不要把正在写入的单个 SQLite 文件直接复制后当作一致的完整备份。
3. 将新程序放在同一数据目录旁，保持 `data_directory` 和端口设置，不要让新旧版本同时占用同一端口/存储。
4. 启动新程序，检查运行准备。模型元数据或接入配置变化时完整重启 Codex；只有该版修改工具定义时才需要在 ChatGPT 刷新工具。

修改 `data_directory` 会选择另一份存储，不会自动搬迁登录与任务。二进制不包含开发机数据；用户文档单独交付，不能为了打包文档把整个 `data` 复制到公开发行包。

### 恢复 Codex 路由

“配置工具连接”中的**恢复接入前配置**恢复备份的旧路由，它可能是另一个网关；**恢复 Codex 官方路由**则清除桥接路由与 Web 默认模型。预览后保存/确认预期操作，再完整重启 Codex。

恢复路由不等于删除项目文件或聊天历史。网页模型无法直接解密其他提供方的加密上下文，详见[历史续接 FAQ](faq.zh-CN.md#history)。

### 进度停住时

先看运行准备，再查受影响任务的时间线，区分生成、等待工具/审批、压缩交接和明确失败。网页残留“连接中断”提示，不能单独证明工具已经停止。可能已经执行过的写入操作，不要反复重发。

连接器失败、模型缺失、409 冲突、中断及 JSON 解码问题见 [FAQ](faq.zh-CN.md)。提交问题时提供版本、操作系统、时间、模型/档位、完整错误码及脱敏时间线；移除密钥、Cookie、本地令牌和私有提示词。
